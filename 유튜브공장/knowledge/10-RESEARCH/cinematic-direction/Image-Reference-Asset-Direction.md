# 이미지·레퍼런스·에셋 연출 원리

이 문서는 이미지 생성과 수정에 관한 외부 자료를 MK Visual Director의 에셋 설계 원리로 다시 쓴 것이다. 특정 공급자의 모델을 자동 선택하거나 호출하기 위한 문서가 아니다. 모델 이름, 지원 비율, 레퍼런스 한도, 편집 성능 같은 제품 주장은 변할 수 있으므로 실제 제작 전에 공식 UI와 공식 문서에서 다시 확인한다.

핵심 목적은 이미지 한 장의 멋보다 다음 영상 숏에서 사용할 수 있는 일관된 에셋을 만드는 것이다.

## 1. 요청을 구성 요소로 분해 — IMG-001

이미지 요청을 받으면 먼저 다음을 분리한다.

- 핵심 목적: 캐릭터 기준, 장소 기준, 소품 기준, 최종 프레임, 부분 수정 중 무엇인가
- 주체: 사람, 공간, 물체, 문자, 재질
- 맥락: 시대, 기능, 이야기 위치, 사실성 수준
- 출력 제약: 화면비, 단일 이미지 또는 시트, 생성 또는 수정
- 이미 주어진 것과 아직 정하지 않은 것

“멋진 장인 작업장”이라는 한 문장을 바로 프롬프트로 늘리지 않는다. 이 이미지가 정체성 기준인지, 공간 지도인지, 첫 프레임인지에 따라 필요한 정보가 달라진다.

## 2. 모호성과 실패 위험 진단 — IMG-002

세부를 추가하기 전에 결과를 흔들 모호성을 찾는다.

- 카메라 위치와 프레이밍이 비어 있는가?
- 주광 방향과 대비가 비어 있는가?
- 주체 수와 우선순위가 불명확한가?
- 팔레트가 참고 이미지와 충돌하는가?
- 사진이 필요한데 일러스트 표현을 유발하는 말이 있는가?
- 여러 인물의 정체성이 합쳐질 위험이 있는가?
- 문자·문신·브랜드 형태가 뭉개질 위험이 있는가?
- 수정 요청이 원본 전체 재생성으로 번질 수 있는가?
- 설명이 길지만 핵심 고정점은 약한가?

진단 결과는 질문을 위한 것이 아니라 어떤 잠금이 필요한지 판단하기 위한 것이다.

## 3. 작업 종류에 따라 생성 경로를 선택 — IMG-003

인물 기준, 장소 기준, 소품 기준, 기존 프레임 수정, 재질 보정, 극소 부위 수정은 서로 다른 작업이다. 하나의 모델이나 도구가 모든 일을 가장 잘한다고 가정하지 않는다.

경로 선택 기준:

- 새로 만들 것인가, 기존 프레임을 보존하며 바꿀 것인가
- 정체성 일관성이 핵심인가
- 공간의 다른 각도를 만들어야 하는가
- 정확한 문자나 제품 표면이 핵심인가
- 최종 결과가 영상 생성의 레퍼런스인가, 합성용 레이어인가
- 원본 픽셀 보존이 얼마나 중요한가

외부 자료가 특정 제품군을 캐릭터·장소·수정·재질 보정에 추천하더라도 이는 검증되지 않은 공급자별 관찰이다. 유튜브공장에서는 `config/topview-capabilities.yaml`, 로컬 모델 잠금, 실제 파일럿 결과를 우선하며 사람이 현재 UI에서 최종 경로를 선택한다.

## 4. 상세 모드와 즉시 실행 모드 — IMG-004

모호하고 되돌리기 어려운 요청에는 최대 세 가지 핵심 질문으로 빈칸을 채운다. 목표와 입력이 이미 구체적이면 중요한 오류만 바로 고쳐 실행 가능한 지시를 만든다.

질문은 미학 취향을 무한히 묻는 것이 아니라 결과를 갈라놓는 선택에 집중한다. 예: 이 사진은 인물 정체성 기준인가, 공간 구도 기준인가? 정확한 문자는 생성 이미지 안에 있어야 하는가, 후단 합성인가?

## 5. 결과물 중심의 전달 — IMG-005

작업자에게는 최종 지시를 먼저 주고, 그 뒤에 무엇을 고정했는지 짧게 설명한다. 복잡한 자산은 역할·잠금·주의점을 표로 정리할 수 있지만, 내부 분석 과정이나 장황한 이론을 작업 지시보다 앞세우지 않는다.

유튜브공장에서는 최종 전달 단위가 프롬프트 한 덩어리가 아니라 다음 묶음이다.

- 에셋 역할
- 이미지 지시
- 레퍼런스 역할
- UI 설정
- 유지할 항목과 제외할 항목
- 예상 파일명과 저장 경로
- 다음 영상 숏에서의 사용 위치

## 6. 자연스러운 문장과 신호 밀도 — IMG-006

서로 관계없는 품질 키워드를 쌓기보다 주체·행동·공간·빛·재질·카메라를 인과적인 문장으로 연결한다. 설명이 길수록 좋은 것이 아니며, 각 문장이 결과의 다른 부분을 통제해야 한다.

반복되는 미사여구, 일반적인 고품질 표현, 서로 충돌하는 스타일 이름은 제거한다. 정체성·구도·빛·재질처럼 잃으면 안 되는 신호는 짧더라도 구체적으로 쓴다.

## 7. 원하는 상태를 긍정적으로 정의 — IMG-007

생성 지시는 원하지 않는 것의 목록보다 원하는 화면 상태를 먼저 말한다. 사람이 없는 거리라면 비어 있는 거리의 구조와 흔적을 묘사하고, 깨끗한 재질이라면 표면의 실제 상태를 설명한다.

제거가 목적이 되는 이미지 수정에서는 제거 대상과 그 자리를 채울 실제 배경을 함께 지정한다. 단순히 “없애라”로 끝내면 빈 공간이 임의로 채워질 수 있다.

## 8. 화면비·해상도는 UI 설정으로 분리 — IMG-008

화면비와 해상도는 장면 문장 안의 장식 문구가 아니라 작업 화면에서 고정할 설정이다. 프롬프트에는 “수평으로 넓은 공간 구도”, “세로 전신 프레임”처럼 구도 결과를 쓸 수 있지만, 플랫폼 파라미터 표기와 혼합하지 않는다.

TopView 수동 전달팩은 설정과 장면 지시를 분리해서 제공해야 하며, 작업자는 실제 화면에 보이는 값을 캡처해 반환한다.

## 9. 모호한 분위기보다 기술적인 빛과 재질 — IMG-009

“영화 같은 조명”만으로는 결과를 제어하기 어렵다. 광원의 종류·방향·크기, 피사체와 배경의 밝기 관계, 대비, 반사 방식, 표면 마감처럼 관찰 가능한 속성을 쓴다.

재질도 이름과 상태를 함께 둔다. 방짜유기는 단순 금속이 아니라 망치 자국, 산화 정도, 반사 폭, 가장자리 마모처럼 제작 사실을 드러내는 표면이 중요하다. 재질 설명은 역사적 사실과 충돌하지 않게 증거와 분리 검토한다.

## 10. 팔레트의 위계 — IMG-010

주조색, 보조색, 강조색의 비중을 정하면 여러 에셋의 시각 언어를 맞추기 쉽다. 비율은 절대 규칙이 아니라 화면에서 어떤 색이 면적을 지배하고 어떤 색이 시선을 끌지 정하는 도구다.

팔레트는 참고 사진, 시대 자료, 실제 공간, 채널 문법에서 도출한다. 이미 주어진 색 관계를 무시하고 임의의 유행 팔레트를 덮지 않는다. 재질 고유색과 조명으로 생기는 색을 구분한다.

## 11. 정체성은 기준 자산과 고유 고정점으로 — IMG-011

반복 인물의 일관성을 긴 외모 문장만으로 해결하지 않는다. 승인된 정체성 기준 이미지와 고유 고정점을 함께 사용한다. 고정점은 얼굴 비율, 연령감, 체형, 머리 형태, 의상 핵심, 손의 특징처럼 다른 인물로 바뀌면 안 되는 속성이다.

모든 숏에서 같은 사진 구도를 복제하라는 뜻은 아니다. 정체성 기준은 인물을 통제하고, 새 숏의 카메라·표정·행동·빛은 별도의 연출 지시가 통제한다.

## 12. 사진 결과의 일러스트 드리프트 방지 — IMG-012

참조 시트, 콘셉트, 회화적 표현처럼 해석될 수 있는 말은 사진 결과를 일러스트 방향으로 밀 수 있다. 실사성이 필요하면 실제 촬영에서 관찰할 수 있는 렌즈 결과, 피부·천·금속의 물성, 광원, 입자, 노출 관계를 강화한다.

“만화가 아니다” 같은 긴 금지 목록보다 어떤 사진적 증거가 있어야 하는지 명시한다. 다만 프로젝트가 의도적으로 삽화나 그래픽을 선택했다면 실사 잠금을 강요하지 않는다.

## 13. 문자·문신·실존 인물·브랜드 안전 — IMG-013

이미지 안에 문자가 꼭 필요하면 정확한 문구, 글꼴 성격, 굵기, 색, 배치를 별도 요구사항으로 둔다. 그러나 사실 날짜, 인명, 수치, 공개 라벨처럼 오류 비용이 큰 문자는 생성 이미지에 맡기지 않고 HyperFrames 합성층으로 보내는 것이 기본이다.

문신이나 표식은 “문신이 많다”가 아니라 실제 형태와 위치를 정의해야 뭉개짐을 줄일 수 있다. 실존 인물의 이름이나 보호되는 브랜드·캐릭터를 스타일 지름길로 쓰지 않는다. 필요한 시각 특성을 일반적인 얼굴·체형·시대·재료 표현으로 바꾼다.

## 14. 부분 수정은 변경 최소화와 보존 최대화 — IMG-014

기존 프레임을 수정할 때는 바꿀 대상 하나를 작게 정의하고, 나머지 중요한 속성을 구체적으로 보존한다.

변경 범위:

- 정확히 어느 위치의 무엇을 어떻게 바꾸는가
- 제거 후 무엇이 자연스럽게 이어지는가
- 새 요소가 빛·원근·재질과 어떻게 맞는가

보존 범위:

- 인물 정체성과 표정
- 카메라 위치와 크롭
- 공간 구조와 물체 배치
- 손과 소품의 관계
- 조명 방향, 그림자, 노출
- 색과 재질
- 문자와 로고의 정확한 형태

수정 결과가 원본 전체를 다시 그려야 할 정도라면 부분 수정이 아니라 새 프레임 생성으로 분리한다.

## 15. 레퍼런스 시트와 에셋 역할 — IMG-015

레퍼런스 시트는 예쁜 이미지 모음이 아니라 앞으로의 제작을 통제할 기준 자산이다. 한 시트에 너무 많은 목적을 섞지 않는다.

- 인물 시트: 정체성, 체형, 의상 핵심, 표정 범위
- 장소 시트: 평면 관계, 주요 방향, 재료, 랜드마크, 시간대
- 소품 시트: 여러 각도, 크기 기준, 재질, 사용 상태
- 구도 시트: 화면 배치와 여백
- 재질 시트: 표면의 거칠기, 반사, 마모, 오염

각 파일은 `reference_bindings`에서 하나의 주 역할을 갖는다. 여러 역할이 필요하더라도 무엇이 우선인지 분명히 한다.

## 16. 제품 기능 주장의 검증 경계 — IMG-016

외부 스킬이나 사용자 글에 적힌 모델별 장점, 최대 해상도, 화면비, 편집 순서, 레퍼런스 제한은 연구 후보일 뿐이다. 다음과 같이 처리한다.

1. 원문의 날짜와 해시를 보존한다.
2. 공식 화면 또는 공식 문서에서 현재 상태를 확인한다.
3. 같은 입력으로 작은 파일럿을 수행한다.
4. 정체성·구도·텍스트·재질 보존을 실제 출력으로 비교한다.
5. 검증 전에는 레지스트리의 기본 활성 규칙으로 승격하지 않는다.

이 문서의 공급자 관련 내용은 `REFERENCE_ONLY`이며 자동 라우팅의 근거가 아니다.

## 17. 반대 각도는 기존 배치의 재계산 — IMG-017

같은 장소의 반대 각도나 옆면을 만들 때 원본의 좌우 배치를 그대로 복사하면 공간이 거울처럼 틀어질 수 있다. 새 카메라 위치에서 각 물체가 화면 어느 쪽에 보이는지 다시 계산한다.

장소 지도에는 실제 세계의 기준 방향과 물체 관계를 두고, 각 프레임에는 카메라 기준 화면 위치를 별도로 둔다. 새로운 각도에서도 문, 창, 작업대, 주요 소품의 연결이 가능한지 확인한다.

## 18. 상태 변형과 자산 계보 — IMG-018

같은 인물·장소·소품의 상태가 시간에 따라 바뀐다면 기준 자산과 변형 자산을 구분한다.

- 깨끗한 기본 상태
- 작업 중 먼지·땀·열 흔적
- 손상 또는 마모 상태
- 낮·밤 또는 조명 상태
- 사용 전·사용 중·사용 후 소품 상태

각 변형은 어떤 기준에서 파생됐고 무엇이 바뀌었는지 기록한다. 서로 다른 상태를 동시에 레퍼런스로 넣지 않는다. OpenMontage의 자산 매니페스트가 파일, 해시, 출처, 상태, 선택 여부를 보존한다.

## 이미지 에셋 작업 체크리스트

- 이 파일의 한 가지 주 역할이 정해졌는가?
- 생성과 부분 수정 가운데 올바른 작업 종류인가?
- 주체 수, 카메라, 조명, 팔레트의 모호성이 해소됐는가?
- 정체성·공간·소품 중 어떤 기준이 우선인지 분명한가?
- UI 설정과 장면 문장이 분리됐는가?
- 원하는 상태를 먼저 적었는가?
- 재질과 빛이 실제 관찰 가능한 말로 쓰였는가?
- 정확한 문자는 후단 합성으로 보낼 수 있는가?
- 수정이라면 변경 범위가 하나이고 보존 범위가 충분한가?
- 새 각도에서 공간 배치를 다시 계산했는가?
- 상태 변형의 부모 자산과 변경점이 기록됐는가?
- 제품별 기능 주장을 현재 공식 정보와 파일럿으로 확인했는가?

## 출처 취급

연구 입력은 제3자 미러 사본이며 공식 제품 설명 또는 라이선스 증거로 간주하지 않는다. 이 문서는 원문의 공급자 페르소나, 프롬프트 템플릿, 모델별 단정, 예시를 복제하지 않았다. 활용 가능한 원리를 프로젝트 언어로 다시 작성했고, 시시각각 바뀌는 기능 주장은 별도 검증 대상으로 남겼다.
